# Logo workshop

This repository turns AI-traced logo SVGs into clean geometric reconstructions, then recolors them
in design-system styles.

- **One engine, many logos.** `logokit/` holds everything that is the same for every logo. Each
  logo lives in its own folder under `projects/`, with only what is specific to it.
- **Measured, not eyeballed.** Each reconstruction comes from circle and line fits on the traced
  outline, and is verified against the source with raster metrics and close-ups.
- **Styles as data.** `styles/owlky.py` describes the nine Owlky design styles as light and dark
  palettes. Any project can use them.

## Layout

```
logokit/             shared engine (Python, standard library except compare and preview)
  geometry.py        vectors, Béziers, circle and line fits, intersections, Bézier fitting
  build.py           source parsing, Piece, Builder (build, ref, stubs), Mark, SVG writer, report
  check.py           node counts and tangent breaks, read back from the SVG
  compare.py         raster comparison: metrics, overlay, diff, close-ups, sizes
  theme.py           style variants: gradients, outlines, hard shadows, cut-outs
  preview.py         contact sheet of every variant
styles/
  owlky.py           the nine Owlky styles (Soft, Swiss, Bauhaus, Brutalism, Neo-Brutalism,
                     Editorial, Minimal Mono, Corporate, Nordic), light and dark
projects/<name>/
  source/original.svg        the traced logo (never edited)
  reference/original.png     optional raster reference
  analysis/geometry-plan.md  measurements and the reconstruction plan
  analysis/reconstruction-report.md
  analysis/compare/          comparison images (git-ignored, regenerated)
  construction.py            how this logo is rebuilt: constants, pieces, layers
  theming.py                 layer roles, gradient axes, per-style overrides
  output/reconstructed.svg   the rebuilt mark
  output/styles/             <style>-<light|dark>.svg and preview.png
```

## Set up

The geometry and check steps need only Python 3.11 or later. The other steps use the packages
in `requirements.txt`: compare and preview need numpy, Pillow and SciPy plus `rsvg-convert`
(`brew install librsvg`), and theme needs skia-pathops and fontTools for the hard-shadow and
gap clean-up of the inked styles (without them it still runs, skipping that clean-up).

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

## Commands

```sh
python3 -m logokit reconstruct <project>               # output/reconstructed.svg + deviation report
python3 -m logokit check <project>                     # fails on a tangent break
.venv/bin/python -m logokit compare <project> --scale 4
.venv/bin/python -m logokit theme <project>            # output/styles/*.svg
.venv/bin/python -m logokit preview <project>          # output/styles/preview.png
.venv/bin/python -m logokit all <project>              # reconstruct, check, theme
```

## Add a project

1. Create `projects/<name>/source/original.svg`. Add `reference/original.png` too, if you have one.
2. Run `/logo-geometry-analysis <name>`. It writes `analysis/geometry-plan.md`, which ends with
   decisions for you to approve.
3. Run `/logo-vector-reconstruction <name>`. It writes `construction.py`, then builds, compares
   and iterates until the result matches the source.
4. For themed variants, write `theming.py`, then run `theme` and `preview`. A project usually
   only needs `ROLES`, which marks each layer as `brand`, `accent` or `detail`. The style
   defaults cover the rest.

`projects/owlky/` is the worked example for every step.

## Conventions

- Coordinates in `construction.py` are source units. The writer moves them into a tight frame
  with 48 units of padding and rounds them to 0.01.
- Generated files carry a "Generated by" comment. To change a generated file, edit the
  construction or theming and run the command again.
- Never edit `source/`. Keep measuring scripts outside the repository.
